# פתיחת ה־DLC Pokédex — dlc-dex-unlock-r1

התוספת מדליקה **רק** את הדגל האמיתי `FLAG_DLC_DEX_ENABLE` במנהל הדגלים של המשחק. היא אינה כותבת קובץ שמירה ישירות. היא מיועדת להשתלב בעותק בנייה חדש של r28a, יחד עם texfix ו־rando-dexcount הקיימים.

## מה משתנה

ה־patcher משנה רק את `f_70008d4178` ב־`main_287.c`. אחרי שה־getter המקורי קרא את הדגל והחזיר false, מתבצעת קריאה לעזר `za_dlc_dex_unlock_pump`. כאשר הדגל כבר true אין קריאה לעזר ואין העתקת מצב מעבד.

העזר מאמת מחדש readiness ב־`0x700610e100`, את hash הדגל בדסקריפטור `0x7003e26880`, ואת מצביע מנהל הדגלים ב־`0x7003ec3328`. הוא שומר את **כל** מבנה `Cpu`, כולל SIMD, NZCV, מצב exclusive monitor ו־SP; קורא את הדגל דרך getter מקורי; ואם הוא כבוי, קורא setter מקורי עם bool=1 ומאמת את התוצאה שוב באמצעות ה־getter. לאחר מכן הוא משחזר את כל `Cpu` ומחזיר את ערך ה־readback האמיתי למקום החזרה המקורי. אין החזרה קבועה של true.

אין cache של “כבר הופעל”: טעינת שמירה אחרת באותו תהליך תיבדק שוב. guard אטומי מונע כניסה חוזרת בלי להמתין. אין thread חדש, הקצאה או מצביע guest הנשמר בין קריאות. ההפעלה מתבצעת כשמגיעה הקריאה הראשונה ל־getter זה לאחר מוכנות המנהל, ולא על ידי שינוי שמירה מחוץ למשחק.

לא משתנים `FLAG_DLC_ANOTHER_DIMENSION_ENABLE`, דגלי Donuts או `SYS_WORK_DLC_PHASE`. לא נפתחות משימות או מתווספים פוקימונים על ידי העזר.

## ראיות בקוד 2.0.2

- `main_287.c:633–689`, ‏`f_70008d4178`: readiness, דסקריפטור הדגל וקריאת getter.
- `main_012.c:843–1054`, ‏`f_70000393b8`: קריאת hash מ־`x1+0`, חיפוש במפות המנהל, קריאת bool מ־`node+0x18`.
- `main_306.c:1380–1477`, ‏`f_70009d0114`: מקבל manager ב־x0, מצביע hash ב־x1 ו־bool ב־x2. מחפש רשומה קיימת, וכשנמצאת כותב `x2&1` ל־`node+0x18`; אין יצירת רשומה חדשה. קריאת ההמשך `f_7002ab3298` ב־`main_1058.c:632–708` היא חיפוש בלבד.
- `main_115.c:7562–7955`, ‏`f_700033f8d8`: קורא את אותו דסקריפטור ישירות. כתיבת הדגל האמיתי גורמת גם לקורא זה לראות true.
- hash הדגל: `58e63b00d271631f`; ה־system-flag save block הוא `ED6F46E7`. אין שימוש ב־setter של PKHeX.

ה־getter וה־setter דורשים בפועל רק את שמונת הבתים הראשונים של המפתח. הדבר נבדק בהרצת **הפונקציות המתורגמות האמיתיות** מול מפות סינתטיות עם דסקריפטור ישיר, כולל שני מסלולי fallback, ולא רק מול stubs.

## תופעת לוואי קיימת של פתיחת המסך

בקוד המשחק, פתיחת ה־Pokédex קוראת ל־`f_7002c8b53c` ב־`main_1080.c:23702–23744`. כשהדגל פעיל, מנהל ה־Pokédex מוכן ו־Mankey (species 56) עדיין אינו מסומן Seen, הפונקציה קוראת ל־`f_700052da9c` עם form=0. מסלול זה מעדכן את SeenMask ב־entry+4 ואת ביט המגדר ב־entry+0xb (`main_177.c:11192–11221`). הוא אינו משנה את CaughtMask ב־entry+0 ואינו מעניק פוקימון. זהו קוד משחק קיים שנעשה נגיש לאחר ההפעלה; העזר אינו קורא לו.

מסקנה זו מבוססת על קריאה סטטית של המסלול. אין כאן טענה שניסוי פתיחת המסך על קונסולה או ניסוי שמירה/טעינה כבר בוצעו.

## בנייה ושילוב

```sh
python3 port/dlc-dex-unlock/prepare_dlc_dex_hook.py \
  --aot /path/to/original/aot \
  --nso /path/to/original/game/exefs/main \
  --out /path/to/new/private-build/generated
```

ה־patcher דורש build ID ‏`b1f12fd919eae86ab8a978317677e64bce443d1f`, ‏SHA-256 מקור מדויק ועוגן יחיד בתוך הפונקציה. הוא מסרב לפלט שדורס את המקור או פלט קיים שונה. הפלט מכיל `main_287.c` ו־`dlc-dex-hook-manifest.json`. אין לשמור את C המתורגם בחבילת קוד הכלים או ב־Git.

יש לקמפל את הפלט אל member ‏`main_287.o` של **עותק** ה־archive המשולב של r28a, ולהוסיף לקישור את `za_dlc_dex_unlock.o` מקובץ העזר כאן. include של העזר צריך להצביע ל־`source/runtime` הקיים. לא משתנים main_261.o/main_310.o של dexcount או אובייקטי runtime של texfix.

לבניית trace: ‏`-DZA_DLC_DEX_TRACE=1 -DZA_DLC_DEX_KLOG=1`. הפלט משתמש ב־klog וב־stderr הקיימים, רק בשינוי state ועד 16 הודעות לתהליך:

| state | משמעות |
|---|---|
| 0 | המנהל עדיין אינו מוכן |
| 1 | hash דסקריפטור לא תואם; אין כתיבה |
| 2 | מצביע מנהל חסר/לא מיושר; אין כתיבה |
| 3 | הדגל כבר פעיל |
| 4 | setter הצליח ו־readback=1 |
| 5 | setter/readback לא הצליחו; אין טענת הפעלה |

בשביל מצב 4 צפויה שורה עם `before=0 set_ok=1 after=1`. מסלול already-enabled הרגיל מדלג על העזר ולכן אינו מפיק הודעה.

## בדיקות שבוצעו

```sh
bash port/dlc-dex-unlock/test/run-host-tests.sh [AOT_ROOT] [ORIGINAL_NSO]
```

הריצה עברה ב־WSL עם clang-21, ‏ASan ו־UBSan, ב־trace off/on. היא מחלצת זמנית את ה־getter, ה־setter וה־map lookup המקוריים ומריצה אותם עם מפות synthetic, בלי קובץ שמירה ובלי הרצת המשחק. נבדקו שלוש מפות החיפוש; byte diff שמאשר שרק bool היעד משתנה; שימור כל בתיו של Cpu; readiness; דסקריפטור שגוי; מנהל חסר; key חסר ללא יצירת רשומה; reentry; טעינת מצב false חדש באותו תהליך; והפונקציה המקורית לעומת הפונקציה המותאמת כולל fast path. ארבע בדיקות patcher עברו. קומפילציה של כל main_287.c עברה עם אותם defined symbols ו־import חדש יחיד `za_dlc_dex_unlock_pump`. העזר נבנה גם עם trace+KLOG.

הבדיקות אינן מוכיחות ש־DLC Dex פתוח מוקדם בכל מצב משחק, שהשמירה טוענת מחדש את הדגל, או שאין תנאי UI נוסף במסלול שלא הופעל. בדיקת קונסולה עדיין נדרשת במסגרת בדיקות ההתקנה של החבילה.

## שמירה ו־rollback

הכתיבה נעשית למצב הדגלים החי של המשחק; שמירה רגילה עשויה לשמר אותה, וגם Seen של Mankey שנוסף בפתיחת המסך עשוי להישמר. persistence טרם נבדק על החומרה.

החזרת executable קודם מסירה את ההתנהגות האוטומטית להבא. היא **אינה** מבטלת דגל או Seen שכבר נשמרו במשחק. אין מנגנון ביטול דגל בחבילה זו ואין לשחזר אוטומטית שמירה ישנה מעל התקדמות חדשה. בדיקות rollback צריכות להבחין בין שחזור executable לבין מצב השמירה.
