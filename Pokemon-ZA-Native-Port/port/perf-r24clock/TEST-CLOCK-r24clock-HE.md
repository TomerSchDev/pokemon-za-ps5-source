# הוראות בדיקה: r24-clock — PPSA91762

29.10.2026. בנייה: `artifacts/randomizer-r24-clock/PPSA91762/eboot.bin`, SHA-256 `35ee54dacd03b217a30f9e18b7e57f8117a880b859013dee7b005da44b6d573e`.
חזרה בסוף: r23c (`dd1df4862a08eab80a19790bb2b65b351adb8ff1fc3ce893def4a91417786677`), או המצב שהיה מותקן לפני הבדיקה.

**ההשערה:** בפרופיל של r24-prof, ‏67% מהדגימות של ה-render thread עמדו בכתובת אחת ב-libkernel, ומי שקרא לה היו `draw_`, ‏`draw`, ‏`vk_tex` ו-`cbuf_info`. זה מתאים לקריאות `clock_gettime` של מדידת הזמן הפנימית של ה-renderer (בערך 12 קריאות לכל draw). כל קריאה כזו היא syscall, שנמדד בעבר בכ-20 µs על 13.60. r16 מפעיל את המדידה הזו תמיד (`LARECOMP_VK_PROF`). אם ההשערה נכונה, כיבוי המדידה (`vkprof=0`) אמור לקצר הרבה את זמן הפריים.

## חלק 1 — בדיקה מהירה (מריצים קודם)

החבילה נשלחת מוכנה לבדיקה הזו. `perf-r24-options.txt` מכיל רק שני מפתחות פעילים, וכל השאר כהערות:
```
scale=1
force60=1
```
- `scale=1`: פלט 4K, רינדור פנימי 1080p.
- `force60=1`: מצב 60 FPS קבוע. מתחת ל-60 המשחק מאט, וזה צפוי. **זו חבילת בדיקה, לא לשחק בה.**

**שלוש עליות, ABA**, באותה שמירה, באותה נקודה ובאותה מצלמה כמו בבדיקות הקודמות, עם מטמון shaders חם. בכל עלייה שתי מדידות של 20 שניות.

| עלייה | `perf-r24-options.txt` |
|---|---|
| **A** | כמו שנשלח (`scale=1`, ‏`force60=1`). מדידת ה-renderer דלוקה, כמו היום. |
| **B** | כמו A, ועוד שורה `vkprof=0`. מדידת ה-renderer כבויה. |
| **A2** | כמו A (מחזירים את הקובץ כמו שנשלח). |

הקובץ נקרא פעם אחת בעלייה, ולכן כל שינוי דורש עלייה מחדש של ה-title.

**מה לבדוק בלוג של כל עלייה:**
- `[za-r24clock] vkprof...`: ב-B צריך להופיע "LARECOMP_VK_PROF unset", וב-A וב-A2 "profile is on".
- `[za-r24clock] renderer CPU profile (LARECOMP_VK_PROF): on/off`.
- ב-B, שורת `[vk]` מאבדת את השדות `| gpu ... cpu exec ... draw ... submit`. זה צפוי.

**מה לדווח, לכל עלייה (ממוצע שתי המדידות):**
- **FPS**, ‏**p50 / p95** (מ-CSV של ה-observer).
- **קריאות `clock_gettime` לפריים**, לפי סוג thread (render / guest / other), וגם µs לקריאה. מקבלים את זה מ-`analyze_r24clock.py`, שדה `clock_gettime`.
- **GPU busy**: ב-A וב-A2 משדה `gpu` של שורת `[vk]`. ב-B השדה הזה לא קיים. אם רוצים GPU busy בכל שלוש העליות, מוסיפים `gaps=1` **לכל שלוש** העליות באופן זהה (העלות שלו זניחה; ב-r24 כל המונים יחד עלו 0.47%).
- תקלה, תקיעה, השחתת תמונה או קריסה, אם היו.

**סיום:** להחזיר את הבינארי ואת קובצי האפשרויות למצב שלפני הבדיקה, להסיר את `perf-r24-options.txt`, ולאמת את השמירה.

## כללים (כמו בסשנים הקודמים)
- גיבוי שמירה מאומת לפני הבדיקה, ובסוף אימות שה-hash לא השתנה. לא לשמור במשחק.
- לא לגעת ב-PPSA91761.
- **`performance-options.txt` חייב להישאר בדיוק `optimized`**, וכל קובצי האפשרויות של r23c נשארים כמו שהם. החבילה שולחת אותם זהים בבייטים ל-r23c.
- צילומים מחוץ לחלונות המדידה. לשמור את כל ה-intervals, כולל תקיעות.
- אין תפריט פתוח בזמן מדידה.

## ניתוח
```
python port/perf-r24clock/analyze_r24clock.py --klog <klog של העלייה> --csv <measure_<seq>.csv> --out <...>.json
```
התוצאה כוללת את כל השדות של `analyze_r24.py`, ובנוסף:
- `clock_gettime`: קריאות לפריים, ms לפריים, µs לקריאה ומקסימום, לפי render / guest / other.
- `vk_per_frame`: ‏gpu / exec / draw / submit, או null כשהמדידה כבויה.
- `gpu_busy_ms_per_frame` והמקור שלו.
- `clock_notes`: שורות השעון והאפשרויות של העלייה.

## חלק 2 (אופציונלי) — שעון TSC
להריץ רק אחרי חלק 1, ורק אם יש זמן. זהה לחלק 1 בכל השאר: אותם כללים, `scale=1`, ‏`force60=1`, ‏2×20 שניות לכל עלייה.

| עלייה | מפתחות נוספים |
|---|---|
| **C** | `ticks=tsc`. מדידת ה-renderer דלוקה, אבל ה-SDL ticks שלה (`SDL_GetTicksNS`) נקראים מה-TSC (12 ns) במקום `clock_gettime`. |
| **D** | `vkprof=0`, ‏`ticks=tsc`. |
| **E** | `vkprof=0`, ‏`ticks=tsc`, ‏`tsc=1`. גם `plat_now_ns` של ה-runtime עובר ל-TSC. השעון הזה מזין את ה-vsync המדומה, את התזמון ואת זמני ה-kernel. |
| **A2** | כמו A. |

- בעליות C/D/E צריכה להופיע בלוג שורת `[sdl3-ps5] ticks: TSC at ... Hz; check over ... us: largest deviation ... TSC backwards ... clock_gettime ... us a call`. **לדווח אותה כמו שהיא.** זו בדיקת ה-TSC מול `clock_gettime` (1,000 קריאות), והיא מודדת ישירות כמה עולה `clock_gettime` אחד בקונסולה.
- בעלייה E צריכה להופיע בלוג שורת `[ps5] clock: plat_now_ns from the TSC`.
- **עצירה מוקדמת ב-E:** אם מופיע אחד מאלה, לעצור ולעלות שוב בלי `tsc=1`, ולדווח מה נצפה:
  - קצב משחק שגוי (מהיר או איטי מהצפוי במצב 60 הקבוע), או קפיצות זמן.
  - צליל משובש.
  - תקיעות או כל הפרעה בתזמון הפריימים, למשל frames של 0 ms או ארוכים בהרבה מבעליות D.
  - שגיאות שעון בלוג.
- לדווח לכל עלייה את אותם שדות כמו בחלק 1, ובנוסף את שורת בדיקת ה-TSC.
