# שימוש במערכת הבדיקות המקומית

הכניסה היא `zw test` מתוך העותק הקנוני. ההגדרות והיסטוריית העבודות נשמרות מחוץ
לעותקי הפיתוח; כל הסוכנים משתמשים באותו קובץ הגדרות ובתור ה־PC הקנוני.
מצב האימות בפועל: [PERFORMANCE_BASELINE.md](PERFORMANCE_BASELINE.md).
הכללים המחייבים: [AGENT_TESTING_RULES.md](AGENT_TESTING_RULES.md).

```powershell
.\zw test capacity
.\zw test prepare --test-id startup-001 --agent my-agent --build my-build `
  --type render --frames 120 --stop-after-frame 120 --seconds 45 --timeout 60 `
  --out ..\startup-001.json
.\zw test submit ..\startup-001.json
.\zw test work --once
.\zw test status job-REPLACE_WITH_RETURNED_ID
.\zw test results job-REPLACE_WITH_RETURNED_ID
```

ההתקנה הנוכחית כבר כוללת `../local-test-config.json`. במכונה חדשה מריצים פעם אחת
`zw test init`, לאחר שהמשחק וה־runtime החוקיים כבר הוכנו מקומית. אין הורדות,
התקנת שירות, פורט רשת או ענן. Python 3.12+ ו־Pillow הם הכלים הקיימים הנדרשים.

קובץ config.example.json הוא דוגמה להעתקה לשורש סביבת המעבדה; הנתיבים היחסיים
שבו נפתרים ביחס למיקום ההגדרות. אין להפעילו ישירות מתוך docs/testing ללא התאמה.

`prepare` מקבע את חתימות ה־EXE וה־DLL; הוא אינו בדיקה שעברה ואינו מפעיל משחק.
אפשר להוסיף `--game`, `--dll`, `--save-src` ו־`--input` לתרחיש. EXE שונה מה־EXE
הקבוע של הרץ הקיים מוחזר כרגע כ־UNSUPPORTED. אין לשנות את מקור המשחק או את
השמירה המקורית כדי להתאים בדיקה; משתמשים ב־fixture מועתק ובתיקיית פלט חדשה.

`work` מקבל בעצמו תור, מריץ משחק אחד בכל פעם ושומר על הנעילה הקיימת. בלי
`--once` הוא מעבד עבודות עד 30 שניות של חוסר עבודה. ניתן להפעיל עובד רקע עם
PowerShell `Start-Process -WindowStyle Hidden` והפניית stdout/stderr לקבצים.
`capacity` עלול להראות חוסר commit בזמן שסוכן אחר מפעיל משחק; העובד בודק שוב
לאחר קבלת התור. אין להנמיך את סף הקיבולת או לדלג על כרטיס של סוכן אחר.

ביטול: `zw test cancel JOB_ID`; יש להמתין ל־FINISHED ולבדוק ראיית ניקוי.
התאוששות מעובד שנקטע: `zw test recover`. זיהוי תהליך משתמש גם בזמן יצירה,
ושחרור תור מתבצע רק מול הכרטיס המדויק ועם ראיות. תור/נעילה זרים אינם נגנבים.

תוצאת צילום בלבד אינה אישור לנכונות חזותית. השוואה לבסיס מאושר מחייבת מניפסט
עם חתימת בסיס וספים מפורשים. אין החלפת בסיס אוטומטית. Logic נפרד עדיין אינו
נתמך; אין להסיק מספר ticks או תאוצת סימולציה מנתון FPS.

אבן הדרך הראשונה אומתה: ארבע ריצות Full/Render חיוביות עברו, ונתיבי timeout,
ביטול ויציאה חריגה נבדקו במשחק. פרטים, IDs וכשלים שנשמרו בהיסטוריה נמצאים
ב־PERFORMANCE_BASELINE.md וב־IMPLEMENTATION_REPORT_HE.md. הכנת קבצים משתמשת
בבדיקות זמן שיתופיות; Job Object אינו sandbox של קבצים או רשת.

## התקנה וחזרה לאחור של קוד הכלי

הקוד החדש נמצא ב־`tools/local-testing/`, התיעוד ב־`docs/testing/`, וכרטיס העזרה
ב־`workbench/cards/testing.md`. חבילת המקור כוללת patch מצומצם לשילוב ב־zw,
לניסיון חוזר בשגיאות שיתוף של נעילת המטא־נתונים, ולהפניות AGENTS. היא אינה
כוללת runtime, משחק, שמירות, מפתחות או token של תור. בעותק הנוכחי השילוב כבר
בוצע; ה־patch מיועד גם לסקירה, ולא להחלה כפולה על הקבצים שכבר עודכנו.

לפני הסרת הכלי יש לסיים או לבטל את העבודות של העובד שלו ולאמת שעץ התהליכים
נעצר. מסירים רק קבצים ושורות שנוספו במשימה זו, תוך שמירת היסטוריית התוצאות
וכל שינוי של עבודה אחרת. אין להשתמש באיפוס Git גורף. הפקודות הישנות `zw pc`
נשארות זמינות. אין שינוי התקנה או חזרה לאחור בקונסולה במסגרת משימה זו.
