# ניקוי תוצרי ביניים בסוף כל בנייה

הוראת תומר מ־1 בנובמבר 2026 מחייבת את כל פרויקטי Z-A וכל הסוכנים: בנייה אינה מסתיימת בהשארת כל קובצי הביניים וכל תיקיות הניסוי. לפני בנייה מגדירים מהו קלט, מהו תוצר סופי, מהי ראיה נדרשת ומהו קובץ ביניים זמני; אחרי בנייה מוצלחת מנקים את קובצי הביניים שאינם נצרכים עוד.

## שלב סיום מחייב

1. שומרים ומאמתים קודם את התוצר הסופי, החבילה, proof, חתימות, לוגים ומתכון השחזור. משלימים את כל הבדיקות הקוראות את הביניים לפני מחיקתם.
2. מסירים רק קבצים זמניים שנוצרו בעבודה הזאת, בתוך תיקיית output חדשה ומוגדרת. בודקים נתיב מוחלט, containment, סוג קובץ וזהות; לא עוקבים אחרי symlinks, לא מוחקים לפי wildcard גורף ולא מנקים תיקיית מקור או SDK.
3. כל קובץ שנדרש כקלט לבנייה אחרת, ל־check-proof, ל־baseline או ל־rollback נשמר או מועבר בהליך מאומת עם locator עדכני. שם הסיומת ELF או גיל הקובץ אינם הוכחה שהוא זמני.
4. מתעדים cleanup receipt: הקבצים שהוסרו, גדלים, קבצים שנשמרו והסיבה, תוצאות בדיקות השימור ושגיאות. כשל ניקוי אינו מדווח כשלב ניקוי מוצלח.
5. חריג debug הוא מפורש וזמני: רושמים סיבה, בעלים ותנאי סיום. כשל build שומר את הראיות הדרושות לאבחון; לאחר שהתקלה נסגרה מבצעים סקירת ניקוי. אין להפוך חריגים להצטברות בלתי מוגבלת.

ברירת המחדל המקומית היא לשמור את המועמד הנוכחי, baseline עובד ו־rollback הנדרש, ואת הקלטים/הראיות שיש להם צרכן מפורש. אין לשמור עשר תיקיות build מלאות כברירת מחדל. היסטוריה נוספת נארזת לאחסון קר או מוסרת אחרי סקירת תלויות ושחזור; אין למחוק קלט pinned של release כדי לעמוד במספר גרסאות שרירותי. סגירת תלות ישנה היא משימת הגירה, לא היתר להשאיר עץ עבודה לנצח.

## חוזה מסלול za הנוכחי

במסלול הקיים `check-proof` קורא מחדש גם `llvm-pie.elf` וגם `eboot.bin`. הם נשמרים כל עוד החוזה דורש אותם. שני הקבצים `title-stripped.elf` ו־`eboot.elf` הם תוצרי המרה זמניים; לאחר השלמת הבנייה והאימות הם מועמדים לניקוי ברירת המחדל. הניקוי המשותף אינו משכתב proofs ישנים ואינו הופך ראיה חסרה ל־PASS.

ראו את מימוש הניקוי והתיעוד העדכני ב־`tools/za/` ואת דוח המימוש הנלווה. החיבור האוטומטי של מסלול מסוים נחשב מאומת רק אם נבדק בפועל; כלל הסוכנים מחייב גם מתכונים ותיקים שלא חוברו אוטומטית. אין להמציא פקודת cleanup שלא תועדה או להניח שכל סקריפט legacy כבר מנקה מעצמו.

## שטח שהתפנה

גודל לוגי, בלוקים מוקצים ושטח שהתפנה בפועל הם מדדים שונים. hardlinks/reflinks וקבצים פתוחים עלולים לשנות את השפעת המחיקה. מחיקה בתוך WSL מפנה מקום במערכת הקבצים של Linux; אין לדווח על פינוי בכונן C אלא אם הקצאת ה־VHDX ב־Windows אכן ירדה. אין לבצע shutdown, trim או compaction שמפריעים לסוכנים אחרים כחלק מניקוי רגיל.

הכלל משלים את [בדיקת הקלטים](CURRENT_BUILD_INPUT_RULES.md), [מיפוי התלויות](BUILD_DEPENDENCY_AUDIT.md) וכללי המשאבים והקונסולה. הוא אינו מתיר מחיקת assets, שמירות, מפתחות, מקור, frozen inputs, חבילות פעילות או שינוי baseline. הוראות הניקוי אינן מחליפות הרשאת מחיקה מתאימה וסקירת בטיחות של הנתיבים בפועל.
