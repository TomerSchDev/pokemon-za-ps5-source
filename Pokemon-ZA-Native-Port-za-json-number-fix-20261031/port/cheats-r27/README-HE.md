# MONEY בזמן משחק — r27

הקוד כאן מוסיף בקשות חד־פעמיות לכסף דרך האובייקט החי של המשחק. אין סריקת זיכרון ואין מצביע שמור לשימוש מאוחר.

## ההתנהגות

- ברירת המחדל OFF. בחירת סכום אינה מוסיפה כסף. X מבקש פעם אחת ‎10,000 / 100,000 / 1,000,000.
- רק בקשה אחת ממתינה; לחיצות נוספות בזמן ההמתנה נדחות, בלי צבירה ובלי overflow.
- פתיחה מחדש של תפריט המשחק צורכת את הבקשה דרך קורא הכסף של הממשק. המספר בכותרת התפריט כבר הועתק קודם, ולכן ייתכן שצריך לסגור ולפתוח את התפריט פעם נוספת כדי לראות את השינוי. **שמירה מתוך המשחק** היא גם נקודת החלה חלופית, ושומרת את הערך החדש להמשך.
- `NORMAL` / OFF מבטלים בקשה שעוד לא נצרכה. תוספת שכבר הוחלה אינה מתבטלת. אין freeze, ואין שמירה של בקשות בין הפעלות.
- תקרת המשחק נשמרת: ‎9,999,999. ערך חי שכבר חורג מהטווח נדחה בלי כתיבה, והמצב חוזר ל־OFF.
- טעינה ו־Reset של רכיב הכסף מבטלים בקשות ומחזירים ל־OFF. אחרי טעינה, התפריט יכול לבקש שוב באמצעות enable ולאחריו request.
- מונה `applied` גדל רק כשארבעת הבתים השתנו בפועל; לחיצה, בקשה שממתינה ובקשה בתקרה אינן נספרות כהוספה.

ה־patcher בודק build ID ו־SHA-256 מדויק של **כל חמש היחידות לפני כתיבה כלשהי**. הוא כותב עותקים בלבד, דוחה יעד שחופף למקור, דוחה פלט קיים ושונה, ומפיק manifest. אין לשנות את ה־hash allowlist כדי לגרום למקור אחר לעבור.

## ממשק התפריט

`za_money.h` הוא הממשק היחיד. בעת init קוראים `za_money_lifecycle_reset()`. בחירה ב־NORMAL קוראת `za_money_set_enabled(0)`.
ב־X עם סכום: enable, ולאחר הצלחה request. מציגים בנפרד `pending`, `applied`, `ready`, `last_value` ו־`rejected`.
אין להשתמש ב־`moneyPending.fetch_add` הישן, ואין לקרוא לתוספת "ADDED" בזמן שהיא עדיין ממתינה.

ה־callback משתמש ב־atomic flag לא חוסם כדי לסדר קריאות מקבילות מ־guest threads. lookup מתחרה מדלג ומשאיר בקשה שלא נצרכה לקריאה הבאה. צריכת הבקשה היא CAS הכולל generation של הטעינה; OFF/Reset מנצחים בקשה שטרם נצרכה. פעולה שכבר נצרכה יכולה להסתיים בזמן OFF/Reset מקביל. האובייקט נגיש רק במהלך קריאה סינכרונית של המשחק עצמו.

## בדיקות וכלים

- `test/run-host-tests.sh`: ASan + UBSan, ברירת מחדל, one-shot, ביטול, lifecycle, תקרה, ערך לא תקין, null, שמירת הבתים הסמוכים, 16 producers ובנוסף 4 consumers עם 500 בקשות ללא אובדן.
- `test/test_patcher.py`: hashes/build ID, idempotence, שמירת המקור, דחיית alias וקלט/פלט שונה.
- `test/build-pc.py`: relink מבודד של ה־AOT המקורי, חמש יחידות מוחלפות ו־controller מקומי בלבד. אינו משנה מקור, runtime או game data קיימים.
- `test/audit-pc-table.py`: קורא את ה־PE ומוכיח ש־main_fn_ptrs מצביע בפועל אל הסמלים המוחלפים.
- `test/run-pc.py`: עותק שמירה, תיקיית עבודה נפרדת, מקשים דרך מנגנון הבדיקות של המשחק, צילום מה־renderer והפסקה רק של ה־PID שנוצר.
- `test/verify/`: PKHeX קורא hash של SwishCrypto, כסף, checksum של הקבוצה ושינויים בבלוקים. `near-cap` יוצר fixture חדש בלבד ודוחה overwrite.

לבדיקת PC דרוש יעד ASCII, משום ש־MSYS `dlltool` אינו פותח נתיבים בעברית. ה־Zig המקורי נוקה מהמחשב; הבדיקה משתמשת ב־Clang/LLD 21.1.7 ובאובייקטי ה־AOT המקוריים, עם אותו ABI. `pc_compat.c` משמר את ה־import המקורי של setjmp ל־UCRT `__intrinsic_setjmp`. קובצי PC אלה אינם חלק מ־eboot.

## קבלה

רק `evidence/pc-proof.json` עם כל הדגלים הנדרשים כ־true ו־hashes של אותם מקורות מאשר הוכחת PC. אין להסתפק בבדיקת host או ב־DLL שנבנה. בדיקת PS5 היא שלב נפרד, ואינה נובעת מהוכחת PC.

**הוכחת PC הושלמה ב־29.10.2026, על המקורות הסופיים:**

- שמירת בדיקה מקורית: ‎10,384 → בקשת ‎10,000 → ‎20,384. ה־hook נצרך פעם אחת, ו־PKHeX אישר את הקובץ שנשמר במשחק, לרבות hash ו־checksums של הקבוצה.
- fixture נפרד שהוכן קרוב לתקרה: ‎9,999,990 → בקשת ‎1,000,000 → ‎9,999,999. צילום `cap-after-before-save.png` מציג את התקרה **לפני** לחיצת השמירה הראשונה. לאחר שמירה גם PKHeX אישר את התקרה.
- טעינה מחדש של עותק השמירה האחרונה עם MONEY כבוי: ‎9,999,999 בממשק, אפס החלות, ועותק השמירה נשאר זהה בכל הבתים. SHA-256: `2474376ce84c7c8cc52f75d18f6639d87129504fbfce32ca78e5da664f163e59`.
- קובצי המקור של השמירות לא השתנו. כל ריצה השתמשה בעותק וב־PID משלה, וכולם הסתיימו. בדיקות sanitizers, patcher, טבלת dispatch וקומפילציית מקור ה־runtime ל־PS5 עברו.

ה־PC השתמש ב־controller מקומי שקורא לאותו API ציבורי של MONEY. הוא אינו הוכחה להפעלת תפריט ה־PS5 עצמו; את שילוב התפריט ואת בדיקת החומרה מבצע ה־builder/הסוכן הראשי בנפרד. קובצי game data, השמירות וה־DLL הניסויי אינם חלק מחבילת המקורות למסירה.
