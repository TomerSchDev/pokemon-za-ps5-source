# בדיקת API לשמירות — מקור למעבדת צד

המקור הזה מכין בדיקה מבודדת ליכולת להבחין בקבצים, תיקיות וקישורים בלי לעקוב אחרי קישור.
לא בוצעו כאן בנייה, התקנה או בדיקה בקונסולה. אין שינוי במקורות ה־UI שכבר הוקפאו.

זהות הצד הזמנית היא `PPSA91780`, כפי שהוקצתה בתיאום עם סוכן הבנייה. היא **לא אומתה כפנויה**.
לפני פריסה עתידית חייבים לבדוק שאין כותר או תיקיית התקנה קיימים באותה זהות, ולפעול בתור הקונסולה.
המשחק הראשי והשמירות שלו נשארים מחוץ לבדיקה.

משתמשים בתשתית `native-probe` הקיימת, בעותק חדש בלבד: שומרים את ה־renderer, ה־CRT וכלי הבנייה;
מחליפים את `src/main.cpp` ב־`native_main.cpp` ואת `src/probe.cpp` ב־`fs_probe.cpp`, ומוסיפים `fs_probe.hpp`.
בדיקות הזיכרון והרשת של A0 אינן מופעלות. אין כאן framework או מתקין נוסף.

הבונה צריך לאמת את הייצוא של ארבעת ה־API האופציונליים ב־SDK וב־imports המקושרים: `lstat`, `symlink`,
`readlink`, `getdents`. כל אחד כבוי כברירת מחדל באמצעות macro נפרד. API חסר נרשם כ־`UNSUPPORTED_IMPORT`;
כישלון הרשאה נרשם עם קוד ו־errno. הצהרה ב־header לבדה אינה הוכחת זמינות. לא משתמשים ב־raw syscalls,
בדגלים חסרים או ב־`libkernel_sys` כדי לעקוף זאת.

היישום מסרב לכתוב עד שזהותו ב־`/app0/sce_sys/param.json` תואמת לזהות הקומפילציה. הוא יוצר תיקיית scratch
חדשה ב־`/download0` הפרטי. בתוכה נוצרים חמישה עצמים סינתטיים ושני סנטינלים מחוץ לתת־העץ של המחיקה.
הדו״ח שומר rc, errno, type, mode, dev, ino, d_type ודגלי open. המחיקה היא רשימה קבועה של שמות שנוצרו
בהצלחה באותה הפעלה; אין מחיקה רקורסיבית. הסנטינלים והדו״ח נשארים לקריאה.

`PROBE-PLAN.json` הוא מפרט המסירה לבונה, כולל הפירוש המוגבל של התוצאות. הצלחה במחשב אינה מוכיחה התנהגות
בחומרה, והצלחה חלקית ללא יצירת קישורים אינה מספיקה לפתיחת אפשרות מחיקה ב־PS5. גם דו״ח חומרה תקין נדרש
לעבור ביקורת לפני שינוי המוצר; אין שינוי אוטומטי במשחק הראשי.
