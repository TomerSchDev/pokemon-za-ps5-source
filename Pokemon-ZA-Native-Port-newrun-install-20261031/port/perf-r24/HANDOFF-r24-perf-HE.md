## מה שונה מ-r23c

כל השינויים כבויים או זהים ל-r23c כשהמפתח חסר.

**`/app0/perf-r24-options.txt`** — הקובץ החדש, נקרא פעם אחת בעלייה (לשינוי צריך להפעיל מחדש את האפליקציה):
- `gaps=1` — ציר זמן GPU: זמן busy, זמן idle בין הגשות ובתוכן, והיסטוגרמה של פערים (<0.1 / <0.5 / <2 / <8 / ≥8 ms). **ברירת המחדל בחבילה: דלוק.**
- `dcache=cpu` / `tls` — מטמון ה-dispatch של הקריאות העקיפות: לכל `Cpu` (בלי TLS מדומה) או thread-local כמו ב-r23c. בחבילה: `tls`.
- `prof=1` — פרופיל GPU לכל pass (`[gpuprof]`), כל 120 פריימים (או `prof_every=N`). בחבילה: `0`. הפרופיילר של שורת `[vk]` דלוק תמיד, כמו ב-r23c.
- `mode=1920x1080` — מצב פלט VK_KHR_display במקום הראשון (4K). בחבילה: מוער. רשימת המצבים הזמינים נרשמת בלוג בכל עלייה.

**`slot-depth-options.txt`** — מקבל עכשיו 8, 16, 32 או 64 (בדיקת ה-headroom של 1 GiB נשמרה, ובכישלון חוזרים ל-8). גם הפקודה `slot_depth` של ה-observer מקבלת 32/64 (`port/perf-r24/observer/client.py`, ו-`port/perf-r24/console.py --client r24`).

**מונים חדשים** — שורה נפרדת `[za-r24-perf] key=value` בכל חלון של כ-2 שניות, מיד לפני שורת `[vk]`. שורת `[vk]` עצמה זהה ל-r23c.
- `logic` — מה-present הקודם עד ההגשה הראשונה של הפריים הבא.
- `present` — הזמן בתוך קריאת ה-present.
- זמן CPU לכל thread, שישה העסוקים ביותר.
- המתנות ל-`g_klock`: מספר וזמן.
- `flush` / `dcb_submit` / `kick` (ms לפריים) ומספר הגשות AGC ומילים לפריים, מתוך ה-winsys של RADV (דרך `--wrap`, בלי לבנות מחדש את RADV).
- GPU busy, idle בין הגשות, idle בתוך הגשה, והיסטוגרמת הפערים (עם `gaps=1`).

## מה למדוד

אותה שמירה, אותה נקודה ואותה זווית מצלמה בכל השלבים; מטמון shaders חם; מצב משחק מקורי (mode 0); 20 שניות לכל שלב; סדר ABA כדי לנטרל סחיפה.

1. **r23c מול r24** (ברירות המחדל של r24) — לוודא שהמכשור לא מאט.
2. **השאלה המרכזית: האם ה-GPU מחכה בין הגשות?** מ-`gaps=1`: אם GPU busy ≈ 20 ms ו-idle ≈ 16 ms לפריים, והפערים מתרכזים בעמודה של הגשה-לבאה, צוואר הבקבוק הוא בהזנת ה-GPU (ההגשה/ה-kick), לא בעבודה עצמה — וזה הכיוון הבא.
3. **עומק תור:** 16 / 32 / 64 באותה ריצה. לבדוק אם ה-idle יורד או רק עובר ל-`dcb_submit`.
4. **`dcache=cpu` מול `tls`** — משפיע בעיקר על `logic`.
5. **4K מול 1080p** (`mode=1920x1080`, דורש הפעלה מחדש) — זמן GPU של ה-post/present.
6. **`prof=1`** ריצה אחת לפרופיל לכל pass, כדי לראות אילו passes כבדים.

python port/perf-r24/analyze_r24.py --klog <קובץ ה-klog של הריצה> --csv <measure_<seq>.csv> --out <תוצאה>.json

מסכם רק את החלונות שבתוך המדידה ומחלק בפריימים. לצרף לכל שלב: FPS, p50/p95, `logic`, `present`, GPU busy/idle וההיסטוגרמה, `flush`/`dcb_submit`/`kick`, threads ו-klock, ותמונת לפני/אחרי.

## לא אומת בחומרה

- ש-`pthread_getcpuclockid` עובד בקונסולה (אם לא — `threads=-1` בשורה).
- מצב תצוגה שאינו הראשון.
- 32/64 slots על 13.60.
- `dcache=cpu` בזמן ריצה.
- ה-`--wrap` של ה-winsys (אומת ב-disassembly בלבד).
