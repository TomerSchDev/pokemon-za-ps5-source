# הוראות בדיקה: סשן פרופיל ל-60 FPS על r24-prof — PPSA91762

29.10.2026. המטרה: לראות **איפה הולך זמן ה-CPU** כשהמשחק רץ ב-60 FPS, לכל thread ולכל פונקציה, כדי לבחור מה לתקן. ההגדרה שנבדקת: פלט 4K עם רינדור פנימי 1080p.

## רקע
בבדיקה `r24-60fps-4k-hardware-20261029-065039Z` ניסיון ה-60 הגיע ל-**39 FPS** (פריים של 25.6 ms), בעוד ה-GPU עבד רק כ-8 ms לפריים. המגבלה היא ה-CPU:
- ה-executor ב-render thread עובד כ-20.4 ms לפריים, ועוד כ-5 ms הולכים במקום אחר במסלול הפריים.
- סביר שגם ה-thread הראשי של המשחק כבד: במחשב הוא צורך כ-15 ms לפריים, וב-PS5 הליבות איטיות יותר.
- מוני ה-CPU לכל thread ב-r24 לא היו אמינים. פרופיילר הדגימה של r24-prof מחליף אותם.

## עצירה מוקדמת
- אם עם `sample=1` מופיעים תקיעה, צליל משובש, קריסה, `kill_err` גבוה או המתנות שנקטעות (EINTR): לעצור, לעלות עם `sample=0`, ולדווח מה נצפה.
- אם בשורת הסיכום `text=0` או ext% מוצג כ-`?`: הדגימות עדיין שימושיות, רק הפיצול בין עבודה להמתנה חסר. לציין את זה בדוח.

## מה לדווח
לשמור ב-NAS בתיקייה חדשה `r24prof-profile-hardware-<תאריך>`, באותו פורמט: JSON ותקציר בעברית.

1. **FPS ומונים לכל עלייה:** FPS, ‏p50/p95, ‏GPU busy, ‏exec / draw / submit, ‏logic / present, ‏dcb_submit / kick.
2. **עלות הדגימה:** FPS של B מול הממוצע של A ו-A2.
3. **לכל thread:**
   - render thread, ה-thread הראשי של המשחק, ושאר ה-threads העסוקים, עם השמות ממערך ה-threads של הקובץ.
   - כמה מהזמן הוא עובד וכמה ממתין (ext%).
   - 20 הפונקציות המובילות לפי self samples.
4. **פילוח כולל:**
   - קוד המשחק המתורגם (`f_<addr>`).
   - ה-runtime לפי קובץ מקור: exec.c, ‏objects.c, ‏textures.c, ‏kernel.c, ‏dispatch.c ושאר הקבצים.
   - RADV.
   - libc / kernel stubs.
   - המתנות.
5. **הפונקציות הענקיות:** אילו פונקציות `f_<addr>` הן הכבדות ביותר, כדי להשוות לרשימת ה-giants שמקומפלים ב-`-O0` (ניסוי המחשב בודק זאת).
6. כל שגיאה, השחתת תמונה, תקיעה או קריסה.
